# 目标驱动智能体设计

## 与旧流水线区别

旧 C ReviewAgent 的分块评审本身仍是固定流程，本版没有把它改名冒充自主智能体，而是在其外层新增 AgentRunner：每次由决策策略根据目标和已完成观察选择下一动作，工具调用后重新决策。

真实 ModelPolicy 复用 C 的固定 DeepSeek 客户端，通过 JSON 对象协议返回 action/query/focus/answer。严格白名单与字段长度校验；不采用任意代码执行。OfflinePolicy 是明确的确定性规则演示，不具备 LLM 自主规划能力。

## 数据与状态

迁移 004 为 desktop_tasks 添加 execution_mode、goal、parent_task_id、intent_digest、agent_context、agent_answer、termination。agent_steps 保存 task_id/seq/action/status/label/observation_json，事务内写入并追加 desktop_events，使已有 WebSocket 续传同时驱动工具记录。

任务生命周期沿用 A：awaiting_confirmation → queued → running → completed/failed/cancelled。ask_user 不是后台挂起线程，而是 completed + termination=needs_input，用户补充后创建 parent_task_id 关联的新任务，并重新确认；step_limit 也是明确停止的 completed，不代表任务目标成功。

所有公开工具观察持久化，可包含原文；不保存隐藏思维链。C 调用继续写脱敏 desktop_audits，决策调用以 plan 记录状态/白名单选择，未实现真实 token/费用计量。原始模型响应和凭据不写日志。

## 安全边界

确认绑定选段摘要、目标、上一轮公开摘要、provider 与执行模式。工具只能访问这份 TaskInput 的已确认选段。格式工具不访问全文元数据；对局部结构缺失改为 needs_review，不能推断全文缺失。检索只访问 B 本地参考目录；C 只获得确认选段与任务重点。

8 次决策、2 轮内容评审、240 秒总时限、重复参数拦截、动作白名单。内容评审分块/重试仍受 C 原限制，因此不能把2轮理解为2个HTTP请求。材料中的指令当作不可信数据，无法通过动作协议执行 shell、任意 URL、文件写入。

运行时先原子认领，C 子任务使用 Capture Gateway 不提前提交；只有外层最终结果提交。取消通过事件循环 cancel，终止后工具步骤不保留 running；服务重启不自动重发模型。

## 结果边界

C 结构化结果校验逐字原文和标准；多轮报告保留在各 review_content 观察的 validated_result，结果页取最后一轮。综合摘要是模型自由文字，未做逐句引用校验，界面显式提示。

历史只携带上一轮公开目标/回答，不是全量记忆；摘要可能有引用，每轮确认页完整展示。新版本标注 same_version=false，旧记录不覆盖，不自动应用旧建议。

## D 与后端分工

D 实现目标输入、操作可见、补充要求、重新授权、任务取消、定位与版本管理。新增 app/agent_runtime.py 是整合运行时，C 原引擎作为工具保留。若团队以后切换 AgentSDK，可替换 ModelPolicy/AgentRunner 调度层，但必须保持授权、证据与存储契约。

# 合并与启动说明

## 1. 基线与来源

以提供的 A(1).zip 内 wensai 本地 FastAPI/SQLite 工程为基线。来自 WenSai-Backend.zip 的仅是 B 的 app/material_review 和 C 的 app/review_agent 独立包，以及它们的测试/样例。不启动另一套 PostgreSQL、Redis、Celery 或 AgentSDK 云端入口。

不要把两个同名 app 目录直接互相覆盖。交付 backend 是便于查看/运行的完整参考，不表示授权覆盖团队的最新修改。

## 3. 数据库

A 的 db.initialize 启动时按连续编号自动迁移，保留 001→002→003→004。不要手工重复执行 SQL，不要重置 user_version。004 与智能体代码必须同时部署，desktop DTO 已读取 004 新字段。

新增 C 结果保存在 desktop_tasks.result_json，保留可空总分，不写入旧 A 的必填数字报告表。desktop_events 为任务递增 seq；agent_steps 保存公开动作与观察，可能含原文；desktop_audits 为 C 脱敏调用记录。

数据仅本机使用，先停服务再备份整个 data（数据库与材料文件一起）。自动迁移已在新库测试，真实团队历史数据升级/回滚还须在副本验收；不要让旧程序重新打开已升至004的库。

## 4. 启动与前端配套

Python 3.12，运行安装环境.cmd 创建 .venv 并安装 backend/requirements.txt，再运行启动问赛.cmd。后台实际执行 .venv/Scripts/python.exe backend/serve.py，仅监听 127.0.0.1:8765。关闭服务 Ctrl+C。

serve.py 将根目录 frontend/dist 挂载到 /；D 源码包解压到 frontend，**不是 frontend/frontend，也不是把文件散放 backend**。默认真实接口 http://127.0.0.1:8765；开发 D 使用5173端口（A默认CORS允许该源）。如更改端口，还须更新前端 API base 并重新构建，不能只改服务端。

后端健康检查 GET /health，文档 /docs 和 /openapi.json。未放前端时 / 返回404是正常的，不表示API没启动。权限/来源限制保留 A 原策略，不要为了能打开 file:// 页面而放宽所有 Origin；独立HTML只可用明确 Mock 演示。

## 5. 测试与模型

运行测试.cmd 会安装测试依赖并执行 test_goal_agent、test_desktop、test_adapters、task_b_tests、task_c_tests。指定范围既有验证69项通过；原 A 全量验收未重跑。既有验证细节另附，整理后亦重新运行这69项。

默认 Mock 在本机真实执行B工具和任务循环，但决策策略是规则演示，C只匹配教学样例。真实模式复用C固定DeepSeek端点/配置，通过系统凭据库读取Key；先在本机配置，再由用户逐次核对文字/目标/历史摘要并明确确认。未确认不得调用。

真实模式最多8次决策、2轮内容评审、240秒；每轮内容可能分块重试，不能当成总共只调用模型两次。HTTP模拟已测，真实DeepSeek质量/连通性/费用未验收。不要以离线69项通过声称研究效果已证实。

交付中未包含当前机器的测试ACL辅助脚本、隔离Python依赖、密钥、node_modules、用户data。受限Windows测试曾需仅测试进程临时目录ACL兼容，生产权限策略未更改；普通Windows实机权限仍需团队验收。
